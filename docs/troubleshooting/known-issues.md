# 진단과 알려진 한계

| 증상                                  | 확인 또는 조치                                                                                                                                                                           |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 앱을 열었는데 소리가 없다             | 엔진 시작, 합성 기타 선택, 입력·출력 미터 확인. Master는 시작 시 최대 −24 dB다. Mute, 시스템 출력과 헤드폰 위치를 확인한다. 라이브 입력은 연결 후 모니터링을 따로 켠다.                  |
| 장치 이름이 비어 있거나 목록이 제한됨 | Chrome에서 localhost 또는 HTTPS로 연다. 입력 연결 버튼으로 권한을 요청한 후 장치 목록을 새로 읽는다. USB 분리 시 재연결 후 직접 다시 선택한다.                                           |
| Left/Right를 선택할 수 없음           | MediaTrackSettings.channelCount가 2 이상으로 보고될 때만 좌우 분리가 가능하다. 장치 Rec Mode와 OS 입력 포맷을 확인한다.                                                                  |
| 출력 선택이 비활성                    | 엔진을 먼저 시작한다. 현재 브라우저의 AudioContext.setSinkId 사용 가능 여부와 장치 권한 범위를 확인한다. 필요시 개인 장치의 운영체제 출력을 사용한다.                                    |
| 파일 또는 IR 로딩 실패                | 오디오 파일은 Chrome이 디코딩 가능한 형식과 100 MiB 이내. 캐비닛 IR은 10초 이하, 32 MiB 이내, 모노·스테레오 RIFF WAV를 사용한다. 디코딩된 파일 버퍼는 메모리를 사용한다.                 |
| NAM이 거부됨                          | 32 MiB 이내의 모노 .nam, 올바른 구조·가중치와 명시된 샘플레이트가 필요하다. Settings에서 모델 레이트를 선택한 후 엔진을 재시작한다. 새 모델 검사 실패 후 기존 기본 DSP를 사용할 수 있다. |
| 프리셋을 복구했는데 모델 소리가 다름  | NAM 모델 라이브러리에서 지문이 일치하는 모델을 적용하거나 원본 다시 연결로 같은 파일을 선택한다. 개별 활성 상태, 전체 Bypass와 Dry 선택을 확인한다.                                      |
| 저장한 NAM 모델이 목록에 없음         | 저장할 때 사용한 브라우저 프로필·접속 주소인지 확인한다. 사이트 데이터를 지웠거나 다른 기기에서 열었다면 원본 .nam을 라이브러리에 다시 추가한다. 프리셋 JSON에는 참조만 들어 있다.       |
| WAV 결과에 예상한 톤이 없음           | A · DRY/전체 Bypass 상태와 각 모듈의 활성 상태를 확인한다. NAM 활성 Wet 내보내기는 미지원이다. 렌더는 선택된 입력 전체와 Master 설정을 사용한다.                                         |
| 짧은 피크가 보이지 않음               | 화면 미터는 표본 창을 읽는 방식이다. 출력 보호는 그래프의 샘플 진폭에 적용된다. 물리 입력 ADC의 클리핑, 채널별 피크, 실제 헤드폰 음압은 별도로 확인한다.                                 |
| 프리셋이 목록에 없음                  | 같은 브라우저 프로필·포트·호스트를 사용했는지 확인한다. localhost와 127.0.0.1의 저장소는 분리된다. 사이트 데이터 삭제 전 JSON으로 내보낸다.                                              |
| USB 입력이 두 번 들림                 | 장비 직접음과 브라우저 처리음을 한 경로씩 확인한다. [Matribox 연결 절차](../audio/matribox-setup.md)                                                                                     |
| 실행 도구가 차단되거나 포트가 사용 중 | Windows는 npm.cmd를 시도한다. 개발 서버·테스트에 필요한 루프백 포트를 확인한다. 회사 시스템 설정 또는 다른 프로젝트 프로세스를 변경할 필요는 없다.                                       |

실제 앰프 캡처의 연주감, 장시간 부하, 브라우저 중단 뒤 복구, macOS 출력 전환, Matribox 물리 왕복 지연은 실기기로 평가할 항목이다. 긴 리버브나 IR 교체 시 잔향이 바뀌고, 우회 중에도 일부 연결 노드가 처리 비용을 사용할 수 있다. [하드웨어 검증표](../testing/hardware-test.md)
