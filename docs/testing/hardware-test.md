## 물리적 왕복 지연 측정

브라우저의 `baseLatency`는 그래프 출력을 오디오 서브시스템으로 전달하는 지연이고, `outputLatency`는 해당 출력 장치에서 재생될 때까지의 추정치다. 진단값은 원래 단위와 함께 기록한다. 기타 입력 변환, 입력 버퍼와 그래프 처리까지 포함한 왕복 지연은 별도로 측정한다. [W3C Web Audio 지연 정의](https://www.w3.org/TR/webaudio/#dom-audiocontext-baselatency)

1. 두 채널을 같은 클럭으로 동시에 녹음할 수 있는 별도 레코더 또는 인터페이스를 준비한다. 낮은 레벨의 짧은 펄스를 적정 임피던스·레벨로 나누어 한 갈래를 기준 채널 A에, 다른 갈래를 Matribox 악기 입력에 보낸다. 장비 직접음이 섞이지 않는 아날로그 소프트웨어 모니터 출력을 채널 B에 녹음한다. 레코더 입력의 모니터 리턴은 끈다.
2. FRETON은 Bypass로 시작한다. A/B의 직접 신호 경로를 같은 신호로 먼저 비교해 계측 채널 간 시간차가 있다면 기록한다. 실제 시험에서 두 채널 첫 유효 펄스의 샘플 위치 차이에서 그 시간차를 보정한다.
3. `지연(ms) = 보정한 샘플 차이 ÷ 레코더 샘플레이트(Hz) × 1000`으로 계산한다. 동일 조건에서 최소 5회 반복하고 중앙값, 최소·최대, 입출력 경로와 샘플레이트를 기록한다. NAM 등 DSP를 켰을 때의 결과는 별도 행에 남긴다.
4. 장비와 유선 헤드폰만 있을 때는 단음을 빠르게 연주하며 연주감과 이중음을 기록한다. 수치 기록란은 Pending으로 둔다.
