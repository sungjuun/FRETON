# NAM 모델별 실시간 렌더 부하

2026-11-27, 같은 750 Hz WAV를 반복 재생하면서 128프레임씩 처리하는 데 걸린 시간을 측정했다. 48 kHz에서 전체 그래프의 95백분위는 NAM 미연결 299 µs, Linear 313 µs, RiffSmith Distorted 820 µs였다. 이 레이트에서 128프레임에 해당하는 오디오 길이는 2,667 µs다.

## 측정 결과

| 엔진 (kHz) | NAM                 | 측정 블록 수 | 중앙값 (µs) | 95백분위 (µs) | 블록 시간 대비 95백분위 |
| ---------: | ------------------- | -----------: | ----------: | ------------: | ----------------------: |
|       44.1 | 미연결              |        2,081 |         141 |           313 |                  10.78% |
|       44.1 | Linear              |        2,080 |         143 |           311 |                  10.71% |
|         48 | 미연결              |        2,262 |         138 |           299 |                  11.21% |
|         48 | Linear              |        2,263 |         145 |           313 |                  11.74% |
|         48 | RiffSmith Distorted |        2,262 |         470 |           820 |                  30.75% |
|         96 | 미연결              |        4,509 |         143 |           293 |                  21.98% |
|         96 | Linear              |        4,506 |         157 |           362 |                  27.15% |

**모델 호환성.** RiffSmith Distorted는 48 kHz를 요구하는 학습 캡처다. 44.1·96 kHz에서는 앱이 레이트 불일치를 알리고 활성화를 거부했다. Linear는 계수 0.25의 단일 탭 검증 모델로, 각 엔진 레이트를 명시한 세 파일을 생성해 시험했다. [캡처 출처와 지문](../../assets/test-audio/riffsmith/README.md)

**관측 범위.** 48 kHz의 세 반복에서 개별 95백분위 범위는 미연결 260~319 µs, Linear 296~373 µs, RiffSmith 775~877 µs였다. 이 환경에서는 RiffSmith를 연결했을 때 그래프 처리 시간이 늘었고, Linear와 미연결의 관측 범위는 겹쳤다. 표의 비율은 해당 그래프의 블록 처리 시간과 블록의 오디오 길이를 비교한 값이다. 시스템 전체 CPU 점유율, 실제 기타 왕복 지연, 장시간 재생 중 끊김 횟수는 이번 측정 범위 밖이다.

## 조건과 재현

- Windows x64 빌드 26200, Intel Core i5-12500, headless Google Chrome 158.0.8127.37, NAM WASM 3.3.0. Playwright 한 워커로 로컬 프로덕션 빌드의 Audio Sandbox를 실행했다.
- 모든 조건에 동일한 0.5초 모노 PCM16 파일(48 kHz, 750 Hz 사인)을 사용했다. 다른 엔진 레이트에서는 브라우저가 WAV를 디코딩하면서 변환한다. 입력 레벨 0 dB, Master −24 dB, 개별 이펙터 꺼짐, IR 미연결, B · WET으로 측정했다. 기준 조건에서는 NAM 파일을 해제한다.
- 모델을 바꾼 뒤 1초간 예열하고 2초간 Web Audio trace를 기록했다. 레이트마다 조건 순서를 한 칸씩 돌려 세 번 반복했다. 각 구간 전후에 출력 RMS를 확인했다. 48 kHz에서 미연결 −43.3, Linear −55.4, RiffSmith −44.1 dBFS였다.
- 표는 세 구간의 블록을 합친 통계다. 95백분위는 처리 시간을 오름차순으로 정렬해 95% 순위에서 올림한 표본이다. 비율은 `95백분위(µs) × 엔진 레이트 ÷ (블록당 프레임 × 1,000,000) × 100`으로 계산한다. 그래프 안에서 실제 경과한 시간을 집계하므로 스케줄링과 trace 기록 비용도 결과에 영향을 준다. [측정 방식 선택 근거](../adr/0009-nam-render-measurement.md)

프로젝트 루트에서 설치된 Chrome으로 실행한다.

```sh
npm run bench:nam
```

Windows PowerShell에서는 `npm.cmd run bench:nam`을 사용할 수 있다. 명령이 타입 검사와 빌드를 마치면 로컬 포트 47137에서 측정한다. 콘솔에 요약과 파일 경로를 출력하고 `.local/nam-benchmark/` 아래에 레이트별 `measurement.json`을 저장한다. JSON에는 환경, 입력·모델 지문, 각 반복의 미터값과 블록별 µs 원자료가 들어 있다. 다시 실행하면 이 디렉터리의 결과를 교체한다. [측정 코드](../../tests/benchmark/nam.bench.ts)
