2026-11-25, Windows · Node.js 22.23.2 · npm 10.9.8 · 설치된 Google Chrome 158.0.8127.37에서 수행했다. 실제 오디오 인터페이스, 마이크, 일렉기타는 사용하지 않았다.

## 실제 오프라인 오디오

체인 순서 검사는 48 kHz, 750 Hz 사인 WAV를 반복 재생하고 EQ의 Middle을 +12 dB, Distortion의 Gain을 90%로 설정했다. Distortion → EQ의 실시간 출력 RMS는 0.032970, 내려받은 Wet WAV는 0.032968이었다. EQ → Distortion으로 옮기면 각각 0.009223과 0.009225가 됐다. 원래 순서로 복원하면 두 측정값 모두 처음 값으로 돌아왔다. Dry WAV는 이동 전후 파일 바이트가 일치했고 전체 Bypass에서 Wet WAV도 같은 파일 바이트를 냈다.

별도의 실시간 NAM 검사에서는 48 kHz, 750 Hz 모노 WAV를 반복 재생하고 다른 DSP 모듈을 모두 우회했다. 분석기 2048샘플에서 2250 Hz 진폭을 750 Hz 진폭으로 나눈 값은 Dry 0.0000190, RiffSmith Distorted 0.10988, NAM 바이패스 후 0.0000190이었다. 같은 테스트에서 44.1 kHz 불일치 거부와 명시적인 48 kHz 재시작을 확인했다. 이 결과는 학습된 모델의 신호 처리에 대한 측정이다. [재현용 캡처](../../assets/test-audio/riffsmith/README.md)

48 kHz OfflineAudioContext에서 공통 DspGraph로 렌더한 Float32 샘플을 비교했다. 입력은 직접 생성한 사인·임펄스·합성 현 신호다.

| 검사             | 관측값                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------- |
| +6 dB 게인       | 200 Hz 사인의 RMS가 1.9953배                                                            |
| Bass +10 dB      | 40 Hz에서 RMS가 3.1083배                                                                |
| 하드 왜곡        | 600 Hz 3차 성분 / 200 Hz 기본음 진폭 비 0.3333                                          |
| Delay            | 100 ms 부근 첫 반복 peak 0.0750                                                         |
| 생성 리버브      | 임펄스 이후 200~5999 샘플 구간 RMS 0.0002274                                            |
| 전체 Bypass      | 고게인 프리셋을 우회한 출력과 기준 신호의 차분 RMS 0                                    |

## Chrome에서 확인한 흐름

- 오버드라이브의 3차 고조파/기본음 진폭 비는 0.26991이었다. 컴프레서(-40 dB, 12:1) 적용 시 두 입력의 정상 구간 RMS 차이는 18.06 dB에서 1.74 dB로 줄었다. 초기 검사에서 단일 출력의 절대 감쇠량을 기대했지만 메이크업 게인 때문에 그 기준이 맞지 않아 두 입력 레벨의 차이를 측정하도록 수정했다. [Web Audio 컴프레서 규격](https://www.w3.org/TR/webaudio-1.1/#DynamicsCompressorNode)
- 같은 이름에 다른 내용이 있는 NAM·IR의 원본 재연결은 거부하고, 일치하는 파일의 바이패스·캡처 유형은 복원했다. NAM 로딩 도중 프리셋을 바꾼 경우에는 늦은 결과가 방금 선택한 모델을 바꾸지 않는지 검사한다.

- 드롭다운 프리셋 변경, 페달 선택, 노브 키보드 조절·초기화, 메뉴 전환, 390px 화면의 가로 넘침 여부를 검사했다. 데스크톱 Virtual Rig 화면 캡처로 배치도 확인했다.
- IndexedDB 저장·즐겨찾기·새로고침 후 선택, JSON 유효성 검사·가져오기·내보내기·이름 변경·복제·삭제, 누락된 IR 재선택 경고를 확인했다.
- 테스트 신호의 실제 미터 응답과 스펙트럼 전환, 생성 WAV 파일의 디코딩·반복·재생·일시정지·탐색·정지, Dry/Wet WAV 다운로드, 엔진 재시작 후 파일 복구를 확인했다.
- 자체 선형 NAM을 브라우저 Worklet으로 처리했다. 계수 0.25 모델의 Wet/Dry RMS 비와 계수 0.5 교체 후 약 2배의 변화를 검사했다. 레이트 불일치 거부·바이패스·해제, 별도 32 kHz 스테레오 IR 디코딩과 잘못된 파일 거부도 확인했다.
- 브라우저가 생성한 실제 스테레오 MediaStream에 두 진폭을 넣어 좌우 전환의 약 4배 차이, 기본 모니터 무음, 모니터 활성 신호와 트랙 정리를 검사했다. 장치 취득·채널 메타데이터·연결 종료 이벤트는 테스트에서 대체했다. 장치 없음·권한 거부와 늦은 권한 응답 역시 API 대역으로 재현했다.

## 기타 없이 수동으로 확인하기

Audio Sandbox에서 Sine을 고르고 엔진을 시작한다. 입력과 출력 파형을 보다가 스펙트럼으로 전환한다. Distortion을 켜고 Gain을 올려 고조파를 본다. Impulse로 바꾸어 Delay의 Time과 Feedback을 조절한다. 리버브를 켜고 끄며 Wet WAV의 꼬리를 비교한다. Silence에서는 이전 이펙터 잔향이 사라질 때까지 기다린다.

파일 드롭을 확인하려면 생성한 test-burst WAV를 파일 영역에 놓는다. 같은 소스에서 6개 프리셋을 비교하고 A · DRY / B · WET을 전환한다. 동일 레이트의 linear NAM과 test-fir IR은 각각 Virtual Rig의 모델 & 캐비닛에서 선택한다. 저장소에 포함한 RiffSmith Distorted는 48 kHz에서 열어 처리음을 비교한다. 실기기 청취 결과는 별도로 기록한다.

실제 USB 입출력·헤드폰 청취·물리 지연·장시간 연주 결과는 [실기기 검증표](hardware-test.md)에 기록한다.
