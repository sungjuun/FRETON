## 실제 오프라인 오디오

**Tremolo**는 44.1·48·96 kHz에서 좌우 레벨과 극성이 다른 스테레오 입력으로 검사했다. Rate 4 Hz, Depth 65%에서 측정한 이득은 세 레이트 모두 0.3500~1.0000이었다. 좌우 이득 차이는 0이었고 Depth 0%에서 Dry와 표본이 일치했다. 1초 입력의 출력도 정확히 1초였다.

48 kHz Chrome 실시간 엔진에서 일정한 진폭의 750 Hz 사각파 WAV를 반복했다. Depth 100%로 두고 Rate를 4 Hz에서 12 Hz로 바꾸자 출력의 진폭이 각각 해당 주기로 변했다. 내려받은 12 Hz Wet WAV에서도 같은 주기를 측정했다. Depth 0%와 개별 바이패스에서는 Dry WAV와 바이트가 일치했다. [Tremolo 설계 결정](../adr/0007-tremolo-depth.md)

**Chorus**는 44.1·48·96 kHz에서 스테레오 임펄스 열을 렌더했다. Rate 2 Hz, Depth 6 ms, Mix 35%에서 48 kHz의 관측 지연은 9.02~20.90 ms, 사인파로 계산한 지연과의 최대 오차는 0.011 ms 미만이었다. 직접음 진폭은 입력의 65%였으며, 좌우의 반대 극성과 2:1 레벨 비를 유지했다. 입력 마지막 표본의 지연음도 파일에 남았다.

500 Hz WAV를 반복 재생하며 Depth 0 ms, Mix 50%로 두면 15 ms 지연음이 정상 구간의 원음과 상쇄됐다. Depth를 올리면 실시간 분석기와 내려받은 PCM16 WAV 모두에서 신호가 돌아왔다. 바이패스한 Wet WAV는 Dry WAV와 바이트가 일치했다. 페달을 옮겨 저장한 뒤 새로고침 후에도 위치와 설정을 복원했다. [Chorus 설계 결정](../adr/0006-chorus-delay.md)

**Noise Gate**는 시드가 고정된 저레벨 잡음과 감쇠하는 750 Hz 사인을 44.1·48·96 kHz 스테레오에서 검증했다. Threshold −30 dBFS, Attack 10 ms, Hold 50 ms, Release 120 ms에서 초기 잡음의 출력 RMS는 0이었다. 48 kHz에서 음의 감쇠와 Hold 구간의 출력/입력 RMS 비는 약 1.00, 490~500 ms 구간은 0.817, 550~560 ms 구간은 0.317, 620~680 ms 구간은 0이었다. 좌우 위상이 반대인 음과 오른쪽 채널만 임계값을 넘는 음에서도 양쪽 게인이 함께 열렸다.

Chrome 실시간 엔진에서 750 Hz WAV를 반복 재생하면서 게이트를 닫으면 출력 분석기 RMS가 0이 되고 내려받은 Wet WAV의 PCM 표본도 모두 0이 됐다. Threshold를 낮추면 다시 신호가 나왔고 바이패스하면 기준 WAV와 바이트가 일치했다. 로드 실패를 주입해 실시간 우회, Wet 내보내기 오류와 우회 후 내보내기 복구도 검사한다.

체인 순서 검사는 48 kHz, 750 Hz 사인 WAV를 반복 재생하고 EQ의 Middle을 +12 dB, Distortion의 Gain을 90%로 설정했다. Distortion → EQ의 실시간 출력 RMS는 0.032970, 내려받은 Wet WAV는 0.032968이었다. EQ → Distortion으로 옮기면 각각 0.009223과 0.009225가 됐다. 원래 순서로 복원하면 두 측정값 모두 처음 값으로 돌아왔다. Dry WAV는 이동 전후 파일 바이트가 일치했고 전체 Bypass에서 Wet WAV도 같은 파일 바이트를 냈다.

별도의 실시간 NAM 검사에서는 48 kHz, 750 Hz 모노 WAV를 반복 재생하고 다른 DSP 모듈을 모두 우회했다. 분석기 2048샘플에서 2250 Hz 진폭을 750 Hz 진폭으로 나눈 값은 Dry 0.0000190, RiffSmith Distorted 0.10988, NAM 바이패스 후 0.0000190이었다. 같은 테스트에서 44.1 kHz 불일치 거부와 명시적인 48 kHz 재시작을 확인했다. 이 결과는 학습된 모델의 신호 처리에 대한 측정이다. [재현용 캡처](../../assets/test-audio/riffsmith/README.md)

48 kHz OfflineAudioContext에서 공통 DspGraph로 렌더한 Float32 샘플을 비교했다. 입력은 직접 생성한 사인·임펄스·합성 현 신호다.

## Chrome에서 확인한 흐름

- Virtual Rig에서 Tab·Enter로 입력 설정을 열어 엔진을 시작하고 750 Hz WAV를 반복 재생했다. 다른 이펙터를 끈 프리셋에서 계수 0.25와 0.5의 Linear NAM을 차례로 적용해 출력 분석기의 RMS가 Dry의 약 1/4과 1/2인지 검사했다. Dry·전체 Bypass와 모델 미연결 시에는 Dry 기준값으로 돌아왔다. 프리셋 변경 후 누락 안내에서 원래 모델을 다시 적용해 1/4 출력으로 복귀했다. Esc와 닫기 버튼의 포커스 복귀, 390 px 너비에서 신호 경로 표시도 검사했다. 같은 검사는 `npm run test:browser -- tests/rig-workflow.spec.ts`로 재현한다.
- 장치 권한 응답은 API 대역으로 지연했다. 첫 요청 취소 뒤 두 번째 요청을 시작했을 때 첫 거부가 두 번째 요청을 종료하지 않았고, 테스트 신호로 전환한 뒤의 늦은 거부도 연주에 영향을 주지 않았다. 현재 요청의 거부는 재시도 때마다 안내했다. 실제 USB 장치와 브라우저 권한 창의 동작은 실기기 검증표에서 확인한다.

- 엔진을 시작하기 전에 RiffSmith Distorted를 라이브러리에 추가했다. 같은 내용을 다른 이름으로 다시 가져왔을 때는 1건, 같은 이름의 다른 Linear 모델까지 추가했을 때는 2건이었다. 새 세션에서 저장한 프리셋을 선택하고 일치하는 캡처를 다시 적용해 바이패스와 사용자가 지정한 캡처 유형을 복원했다. 목록에서 삭제해도 현재 슬롯은 연결되어 있었고, 재접속 시 같은 이름의 다른 모델을 원본으로 선택하지 않았다.
- 잘못된 JSON은 라이브러리에 추가되지 않았다. 44.1 kHz 엔진에서 48 kHz 모델을 선택하면 요구 레이트와 재시작 안내가 나타나고 기존 Linear 슬롯은 유지됐다. 저장소 읽기 지연을 대역으로 주입한 검사에서는 프리셋 전환 후 늦은 파일이 슬롯에 적용되지 않았다.

- 오버드라이브의 3차 고조파/기본음 진폭 비는 0.26991이었다. 컴프레서(-40 dB, 12:1) 적용 시 두 입력의 정상 구간 RMS 차이는 18.06 dB에서 1.74 dB로 줄었다. 초기 검사에서 단일 출력의 절대 감쇠량을 기대했지만 메이크업 게인 때문에 그 기준이 맞지 않아 두 입력 레벨의 차이를 측정하도록 수정했다. [Web Audio 컴프레서 규격](https://www.w3.org/TR/webaudio-1.1/#DynamicsCompressorNode)
- 같은 이름에 다른 내용이 있는 NAM·IR의 원본 재연결은 거부하고, 일치하는 파일의 바이패스·캡처 유형은 복원했다. NAM 로딩 도중 프리셋을 바꾼 경우에는 늦은 결과가 방금 선택한 모델을 바꾸지 않는지 검사한다.

- 드롭다운 프리셋 변경, 페달 선택, 노브 키보드 조절·초기화, 메뉴 전환, 390px 화면의 가로 넘침 여부를 검사했다. 데스크톱 Virtual Rig 화면 캡처로 배치도 확인했다.
- IndexedDB 저장·즐겨찾기·새로고침 후 선택, JSON 유효성 검사·가져오기·내보내기·이름 변경·복제·삭제, 누락된 IR 재선택 경고를 확인했다.
- 테스트 신호의 실제 미터 응답과 스펙트럼 전환, 생성 WAV 파일의 디코딩·반복·재생·일시정지·탐색·정지, Dry/Wet WAV 다운로드, 엔진 재시작 후 파일 복구를 확인했다.
- 자체 선형 NAM을 브라우저 Worklet으로 처리했다. 계수 0.25 모델의 Wet/Dry RMS 비와 계수 0.5 교체 후 약 2배의 변화를 검사했다. 레이트 불일치 거부·바이패스·해제, 별도 32 kHz 스테레오 IR 디코딩과 잘못된 파일 거부도 확인했다.
- 브라우저가 생성한 실제 스테레오 MediaStream에 두 진폭을 넣어 좌우 전환의 약 4배 차이, 기본 모니터 무음, 모니터 활성 신호와 트랙 정리를 검사했다. 장치 취득·채널 메타데이터·연결 종료 이벤트는 테스트에서 대체했다. 장치 없음·권한 거부와 늦은 권한 응답 역시 API 대역으로 재현했다.

## 기타 없이 수동으로 확인하기

Audio Sandbox에서 Sine을 고르고 엔진을 시작한다. 입력과 출력 파형을 보다가 스펙트럼으로 전환한다. Distortion을 켜고 Gain을 올려 고조파를 본다. Impulse로 바꾸어 Delay의 Time과 Feedback을 조절한다. 리버브를 켜고 끄며 Wet WAV의 꼬리를 비교한다. Silence에서는 이전 이펙터 잔향이 사라질 때까지 기다린다.

파일 드롭을 확인하려면 생성한 test-burst WAV를 파일 영역에 놓는다. 같은 소스에서 6개 프리셋을 비교하고 A · DRY / B · WET을 전환한다. 동일 레이트의 linear NAM과 test-fir IR은 각각 Virtual Rig의 모델 & 캐비닛에서 선택한다. 저장소에 포함한 RiffSmith Distorted는 48 kHz에서 열어 처리음을 비교한다. 실기기 청취 결과는 별도로 기록한다.

실제 USB 입출력·헤드폰 청취·물리 지연·장시간 연주 결과는 [실기기 검증표](hardware-test.md)에 기록한다.
