# 시스템 구조

npm workspaces의 `@freton/web`이 `@freton/audio-engine`을 가져온다. 엔진은 React나 Zustand에 의존하지 않는다. 서버에 필요한 데이터 흐름은 이 버전에 없다.

- React Router로 화면을 이동한다. 앱 셸과 엔진 인스턴스는 유지되어 화면 전환으로 연주가 끊기지 않는다.
- 엔진은 명령을 받아 브라우저 그래프를 갱신한 후 변경 이벤트와 리비전을 제공한다. React는 `useSyncExternalStore`로 상태를 읽는다. 시각화는 분석기에서 재사용 배열로 읽고 캔버스와 미터를 직접 갱신한다.
- Zustand는 선택된 이펙터, 대화상자와 로컬 프리셋 목록을 관리한다. IndexedDB 트랜잭션 완료 후 목록을 갱신한다.
- 프리셋 버전 2는 DSP 단위값·활성 상태, 체인 순서, 이름, 즐겨찾기, 파일 이름·SHA-256·활성 상태를 보관한다. 버전 1 JSON과 IndexedDB 레코드는 읽을 때 기존 신호 순서를 복원한다. 원본을 다시 연결할 때 지문을 비교하고, 지문이 없는 초기 참조는 파일명을 비교한다. 내보내는 JSON에 오디오·가중치·장치 ID는 들어가지 않는다.
- 웹 UI와 기본 DSP는 NAM 모델을 요청하기 전에 사용할 수 있다. WASM 및 Worklet은 배포물의 동일 출처 자산이다. 외부 서버 통신 없이 로컬 파일을 디코딩하고 처리한다.

향후 서버는 계정·프리셋 동기화와 오프라인 작업을 맡을 수 있다. 실시간 프레임 처리와 장치 수명은 클라이언트가 계속 소유한다. [엔진 구조](audio-engine.md) · [클라이언트 오디오 결정](../adr/0001-client-side-audio-engine.md)
